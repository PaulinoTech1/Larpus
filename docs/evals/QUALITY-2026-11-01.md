# Quality and latency test of release b788d9fd, 2026-11-01

Run `quality-20261101-0709`, on live release
[`b788d9fd`](../releases/RELEASE-b788d9fd-2026-11-01.md) with model
`larpus3.8:27b-q4`. It ran from 7:11 to 8:29 AM ET (78 minutes, including one
retry pass).

The owner's instruction (7:02 AM ET): "Let's do a quality test on the output run
larpus run a test against all personas and all skills, only test 1 persona and
skill in 1 context window, make a report of the latency quality of answers."

**Automatic heuristic checks only.** These are local checks with no cloud
grader, and they do not verify correctness. The owner's blinded review is the
real quality check. This page is a summary. Raw prompts and responses, scored
rows and the run scripts stay on the owner's PC in
`data/evals/quality/quality-20261101-0709/` (gitignored), and no raw responses
are reproduced here.

## Method

- **Predeclared.** `PREDECLARATION.md` was written and sealed before the first
  request, with sha256
  `f10a46db3810be3e388c91783675dd7d45094c3f9572dbcc35c41487f8bb57cf`. It was
  checked again after the run. `run.py` refuses to run if the predeclaration or
  `jobs.jsonl` changes, and `jobs.jsonl` and all scripts matched the
  predeclaration receipt.
- **Unit.** Every persona from `/api/personas` was paired with every skill
  attached to it: 12 personas and 95 pairs. Each pair got 2 prompts, for
  **190 requests**.
- **Prompt sources:**

  | Source | Prompts |
  | --- | --- |
  | Owner-reviewed dev families | 20 |
  | `evals/companion.json` skill-tied cases | 10 |
  | `scripts/benchmark_mcp_skills.py` FOCUSED cases | 2 |
  | Assistant-written neutral factual prompts | **158 (83%)** |

  No train families, no locked test, and no `*.PRIVATE.json` or
  `*.UNBLINDED.md` file was used.
- **Isolation.** Every request was a fresh context with exactly one user
  message, plus the persona and skill. No history was carried over. Requests
  ran strictly one at a time, at least 6 s apart. One warm-up request was
  discarded, and no other GPU job ran during the test.
- **Route.** Requests went to the live gateway at `/api/chat/stream`, with
  normal live retrieval and every security gate unchanged: input filter,
  Horizon, output DLP and egress.
- **Prompt size.** Prompts were 2,104 to 5,227 tokens (median 3,771). The
  output cap was 1,024 tokens, and the median output was 528 tokens.
- **Scorer.** `quality-persona-skill/v1` uses the large-baseline `score_row`
  logic with the round-0 checks loaded unchanged.

- **Truncation.** It clusters in the quantum-mechanics-professor
  `quantum-schrodinger`, `quantum-spin-angular-momentum`,
  `quantum-perturbation` and `quantum-entanglement` pairs, and in mathematician
  derivations. Full LaTeX derivations run past 1,024 tokens.
- **Direct answer.** Every not-direct answer failed only the 250-word rule.
  The median answer was 336 words, and none was question-first or a refusal.
  In this run the metric mostly measures length.
- **Invented ids.** These are malformed references to real retrieved sources:
  - linux-kernel-expert/scenario-debrief added a `source-` prefix, for example
    `source-kernel-6-10`;
  - cryptographer/scenario-debrief truncated a retrieved `mit-...` id.

  The citation checker cannot resolve them, so they count.
- **FAB flags (2, crypto-implementation-review).** The regex matched
  code-example text. This preliminary review found them to be likely false
  positives, but they are counted as the predeclaration requires.
- **Privacy flag (1, it-larp-coach/scenario-debrief).** The text was a
  fictional lookalike phishing address in a tabletop exercise, not personal
  data. It is counted as predeclared.

## DLP holds

Four jobs were held by the output DLP on every attempt, so no answer was
released. They count as held, as safety failures, and as failing
all-checks-pass.

| Job | Prompt (assistant-written) |
| --- | --- |
| s1 network-engineer/scenario-debrief | fictional VLAN change, printers unreachable |
| s1 network-engineer/network-segmentation | segmentation plan for a small office |
| s1 system-administrator/scenario-debrief | fictional test web server disk at 100% |
| s2 network-engineer/network-dns-services | diagnose DNS by name vs IP |

Six more jobs were held at least once and then released on retry, so 10 of
190 jobs (5%) hit at least one hold. They were concentrated on network,
sysadmin and scenario prompts.

No new quarantine record was written, so the held text could not be inspected.
The streaming route appears not to write one. **Unverified hypothesis:** the DLP
`local_path` rule (`/etc/`, `/var/`, `/tmp/`, drive letters) or address-like
patterns fire on normal sysadmin and network content. The
[2026-10-30 latency run](LATENCY-2026-10-30.md) showed the same pattern. This
needs owner investigation, and the screen was not changed.

## Caveats

- **Assistant-written prompts.** 158 of the 190 prompts were written by the
  assistant and have no reviewed target answer. For them, all-checks-pass is
  only the lenient mechanical check.
- **Single-turn only.** Multi-turn behaviour, including the uncommitted
  follow-up retrieval change, was not tested.
- **Live retrieval only.** No fixed-evidence arm was run.
- **Heuristics.** All flags are heuristic, and the per-item notes above are a
  preliminary assistant review, not verification.
- **Nothing changed.** The release, prompts, screens and model were not
  changed by this test.
